Delivery Event Notifications

Hexagonal Architecture Event-Driven Spring Boot OWASP Secure

Proof of Concept Implementation

The Challenge

Platform Context

  • Cloud-native architecture
  • Event-driven microservices
  • Transactional operations
  • Manages accounts, payments, transactions

Problem Statement

Implement a notification system capable of delivering platform events to client-owned webhook endpoints.

Balance Updated Resource Created Resource Updated Resource Deleted

Core Functional Requirements

FR-1: Subscription Validation

Verify active subscriptions and client ownership before delivery

FR-2: Webhook Delivery

Deliver notifications via HTTPS to client-configured endpoints

FR-3: Retry Strategy

Automatic retries with exponential backoff, avoiding infinite loops

FR-4: Delivery Persistence

Store delivery attempts, errors, timestamps, and final results

FR-5: Observability

Near real-time monitoring with metrics, logs, and traces

Self-Service API

REST API for clients to query and replay notifications

Security Implementation

Authentication & Authorization

JWT Authentication
Stateless tokens with 24h expiration
BCrypt Password Hashing
Strength 10 for secure storage
Custom UserDetailsService
Database-backed user management
BOLA/IDOR Protection
Every query filtered by clientId

Webhook Security

SSRF Mitigation
Blocks private IPs, localhost, metadata endpoints
DNS Rebinding Protection
Validates resolved IP addresses
HTTPS Enforcement
Only secure webhook URLs allowed
URL Validation
Strict format and scheme checking

OWASP Top 10 Mitigations

A01: Broken Access Control

BOLA protection via clientId filtering in all queries

A10: SSRF

URL validation, private IP blocking, DNS rebinding checks

A07: Rate Limiting

Bucket4j on replay endpoint to prevent abuse
